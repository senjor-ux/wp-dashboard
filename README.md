# WP Control

WordPress client management, built as two plugins per the *WP Control – Concept specification*:

| Plugin | Where it goes | Built with | Responsibility |
|---|---|---|---|
| **WP Control Manager** (`wp-control-manager/`) | Your own (agency) WordPress | PHP backend + **React** admin dashboard | Client & website directory, health dashboard, update history, maintenance log, filters, CSV reports, audit history |
| **WP Control Agent** (`wp-control-agent/`) | Every client website | PHP | Securely reports WordPress/PHP versions, plugins, themes, available updates, backups (UpdraftPlus) and security checks |

## Install

1. **Manager:** upload `dist/wp-control-manager.zip` (Plugins → Add New → Upload) on your central site and activate. Open **WP Control** in the admin menu.
2. **Add a website** → copy the pairing token that is shown.
3. **Agent:** install `dist/wp-control-agent.zip` on the client site, open **WP Control → Connection**, paste the token, click **Connect**.

The agent reports hourly, ~90 s after any plugin/theme/core change, and whenever you click **Sync now / Check for updates** in the Manager.

### Local development (localhost, XAMPP, no HTTPS or self-signed certificates)

By default both plugins reject plain HTTP, `localhost` / private-network addresses and untrusted (e.g. self-signed) TLS certificates. So if you host the Manager or a client site on localhost (XAMPP, Local, MAMP, Docker, …), **connecting will fail until you turn on insecure mode on both sides**:

1. **Agent (every local client site):** open that site's `wp-config.php` and add this line **above** `/* That's all, stop editing! Happy publishing. */`:

   ```php
   define( 'WPCA_ALLOW_INSECURE', true );
   ```

2. **Manager:** go to **WP Control → Settings**, turn **Strict transport** off and save.

3. Back on the client site, paste the pairing token again and click **Connect**.

#### Errors that mean you need this

| Where | Error | Fix |
|---|---|---|
| Agent → Connection | *The Manager must use HTTPS. (For local development define WPCA_ALLOW_INSECURE in wp-config.php.)* | Add `define( 'WPCA_ALLOW_INSECURE', true );` to the client's `wp-config.php` |
| Agent → Connection | *A valid URL was not provided*, *cURL error 60: SSL certificate problem* or similar connection errors to a `localhost` / `127.0.0.1` / `192.168.x.x` / self-signed Manager | Same: add `WPCA_ALLOW_INSECURE` |
| Agent → Connection | *Agent requests must use HTTPS.* / *The client site must use HTTPS.* | Manager: turn **Strict transport** off |
| Agent → Connection | *This site is not using HTTPS…* notice | Add `WPCA_ALLOW_INSECURE` (or enable HTTPS) |

> ⚠️ Only use `WPCA_ALLOW_INSECURE` and the disabled **Strict transport** for local testing. Remove the line and turn Strict transport back on for any public site: without them, signed requests travel over plain HTTP and TLS certificates aren't checked.

## Building the dashboard

```bash
cd wp-control-manager
npm install
npm run build     # production build into build/
npm start         # watch mode while developing
```

`build/` is committed so the plugin works without a build step.

## How it works

### Pairing & security
- Each site gets its own 256-bit secret, generated by the Manager and stored **encrypted at rest** (libsodium, key derived from `AUTH_SALT`) on both sides.
- The pairing token (`wpc1.…`) carries the Manager's REST URL, the site id and that secret. Regenerating it rotates the secret and disconnects the old agent.
- Every request in either direction is **HMAC-SHA256 signed** over `METHOD \n route \n timestamp \n nonce \n sha256(body)`; requests older than 5 minutes or reusing a nonce are rejected.
- HTTPS required, `reject_unsafe_urls` on outgoing requests, `manage_wpcontrol` capability on every admin endpoint, REST nonce auth for the dashboard, and an **audit log** of every action (including deletions and exports).
- The agent is read-only — it never modifies the client site.

### Automatic + manual update tracking
The Manager diffs each snapshot against stored components and records **component events** (installed / updated / downgraded / removed) with previous version, new version and detection time. The first snapshot is a silent baseline.

A detected change is shown as **Unattributed** until a technician logs a **maintenance record** (date, performer, category, description, optional duration and notes) and links it to one or more detected changes — the spec's rule that a version change alone doesn't prove who did it.

### Data model
Dedicated tables (`{prefix}wpc_*`): `clients`, `sites`, `agents`, `components`, `update_offers`, `component_events`, `maintenance_logs`, `maintenance_event_links`, `site_checks`, `backups`, `sync_runs`, `audit_log`, `notes`.

### REST API (`/wp-json/wpcontrol/v1`)
| Endpoint | Purpose |
|---|---|
| `POST /agent/pair`, `POST /agent/sync` | Agent → Manager (signed) |
| `GET /dashboard` | Stats, recent maintenance & changes |
| `GET/POST /sites`, `GET/PUT/DELETE /sites/{id}` | Website directory (filters: `search`, `client_id`, `status`=online/offline/pending/updates/critical/backup_stale) |
| `POST /sites/{id}/token`, `/revoke`, `/sync` | Pairing token, revoke agent, pull fresh snapshot |
| `GET /sites/{id}/components`, `/events`, `/backups`, `/checks`, `/activity`, `/notes` | Site detail tabs |
| `GET/POST /maintenance`, `GET/PUT/DELETE /maintenance/{id}` | Maintenance log with event links |
| `GET/POST /clients`, `PUT/DELETE /clients/{id}` | Clients |
| `GET /events`, `GET /activity`, `GET/POST /settings`, `GET /users` | Misc |

Agent endpoint: `GET /wp-json/wpcontrol-agent/v1/snapshot` (signed by the Manager).

CSV exports: `admin-post.php?action=wpcontrol_export&type=sites|maintenance|events` (nonce-protected; cells are escaped against spreadsheet formula injection).

### Extending the agent
```php
// Report backups from another plugin.
add_filter( 'wpcontrol_agent_backups', function ( $items ) {
	$items[] = [ 'id' => 'job-42', 'provider' => 'myplugin', 'status' => 'success',
		'started_at' => time(), 'completed_at' => time(), 'size' => 123456789,
		'storage' => 'S3', 'triggered_by' => 'Scheduled' ];
	return $items;
} );

// Add or adjust security checks.
add_filter( 'wpcontrol_agent_checks', function ( $checks ) { return $checks; } );
```

## Scope (MVP, per spec)
Included: read-only monitoring, secure pairing, site detail views (Overview, Updates, Maintenance, Backups, Security, Activity, Notes), change detection, manual maintenance logging, CSV export.

Deliberately **not** included yet (spec: "later"): remote updates, running backups/scans remotely, advanced vulnerability scanning, notifications.
